  ## Point-based world                                                          
                                                                                
  Use **oriented surface points**, often called *surfels*, rather than cube     
  sprites. A surfel stores position, normal, radius, material, baked            
  indirect-light value, and optionally an emitter flag. Surface elements are an 
  established point-rendering primitive, while progressive blue-surfel work     
  demonstrates GPU-oriented progressive point LOD for complex heterogeneous     
  scenes. [arxiv](https://arxiv.org/pdf/1904.08225v1.pdf)                       
                                                                                
  ```text                                                                       
  Surfel {                                                                      
    local_position: u16x3,                                                      
    normal_axis: u8,                                                            
    radius_or_lod: u8,                                                          
    material: u8,                                                               
    static_light_rgb: u8x3,                                                     
    ao: u8,                                                                     
    flags: u8                                                                   
  }                                                                             
  ```                                                                           
                                                                                
  Render each surfel as a **screen-facing or normal-oriented elliptical         
  splat**, with a soft-but-clipped edge, depth test/write, and blue-noise       
  dither. Do not use transparent round sprites: they create halos, overdraw,    
  and the “particle cloud” look. Instead, use an opaque coverage mask and       
  depth-correct

     GPU Microvoxel Splat Renderer (new main renderer)

     Context

     The CPU splatter (wasm_frontend/src/adapters/cpu_splatter.rs) already
     renders the world the way you want: per-voxel splats, coarse-to-fine LOD,
     front-to-back with budgets. The main GPU renderer (drivers/surface_webgl.rs)
     is still a greedy-quad mesh with a heavy per-pixel fragment shader — smooth
     lighting gradients across big merged quads make it look less voxel than the
     CPU path, and per-pixel lighting (light volume + 4 lights + PCF shadow +
     fog + glow per fragment) is exactly what kills Pi-class GPUs.

     Goal: make the main renderer a GPU instanced voxel-face splat renderer —
     "microvoxel" look (visible voxel grain near, merged voxel planes far),
     per-face
     flat lighting, the existing hero shadow map still visible, and a fragment
     shader cheap enough that a Raspberry Pi (tile-based GPU, WebGL2) outruns
     Minecraft. The greedy mesh is kept, but demoted to shadow-caster +
     collision.

     Key insight that makes this robust: our "splats" are axis-aligned voxel face
     rectangles, not screen-facing discs. An instance is an exposed voxel face;
     the vertex shader emits the exact face quad. That is watertight,
     depth-correct
     geometry (no splat holes/halos), and LOD merging just emits bigger faces.

     Architecture (follows existing port pattern)

     VoxelGrid ─► adapters/surfel_mesh.rs (NEW, portable, natively tested)
                     │  per-chunk SurfelSet: 3 LOD tiers of packed 12-byte faces,
                     │  tier-0 sorted by 2.5 u sub-cell for range draws
                     ▼
     SurfaceMeshPayload (ports.rs, extended) ─► Engine::upload_surfaces
     (unchanged)
                     ▼
     drivers/splat_webgl.rs (NEW SplatRenderer : RendererPort)
        shared base-quad VBO + per-instance attribs, ANGLE-safe instancing
        VS: face quad from normal_axis + per-instance lighting (flat)
        FS: fog + ordered dither only (~10 ops)
        shadow pass: reuses existing greedy-mesh shadow FBO/program

     1. Surfel extraction — wasm_frontend/src/adapters/surfel_mesh.rs (new)

     - PackedSurfel in application/ports.rs (next to PackedVertex), 12 bytes:
     position: [u16;3] (face center, POSITION_FIXED_SCALE), normal_axis: u8,
     size: u8 (multiplier over base voxel scale: 1/2/4), material: u8,
     light: u8, ao: u8, +1 pad. Reuse the exposure/AO/light logic pattern from
     VoxelMapper::map_voxel_grid_with_padding (src/adapters/voxel_mapper.rs)
     — same halo handling as surface_mesh.rs, but no greedy merge: one
     surfel per exposed voxel face.
     - LOD tiers built by downsampling the fine grid (occupancy-majority +
     light-max, same filtering idea as build_mips in cpu_splatter.rs:544):
       - tier 0: fine faces (0.2 u low-spec / 0.1 u high-spec)
       - tier 1: 2× faces, tier 2: 4× faces
     - Tier-0 instances sorted by 2.5 u sub-cell; SurfelSet stores per-cell
     (offset, count) ranges so the driver can range-draw near cells with the
     micro-grain base mesh and far cells with the plain quad.
     - Extend SurfaceMeshPayload with surfels: SurfelSet (built in
     build_surface_mesh alongside the mesh; empty() gets an empty set).

     2. Splat driver — wasm_frontend/src/drivers/splat_webgl.rs (new)

     - SplatRenderer implements RendererPort with uses_surface_meshes() = true
     so the engine feeds it the same SurfaceChunk uploads (engine untouched).
     - Per chunk upload: instance buffers (one per tier), plus the greedy mesh
     VBO/IBO kept for the shadow pass, plus the 3D light-volume texture — copy
     the upload code from surface_webgl.rs::upload_surface; factor
     link_program/camera_matrices into shared pub(crate) helpers rather
     than duplicating.
     - Draw: shared unit-quad vertex buffer (divisor 0) + instance attribs
     (divisor 1), draw_arrays_instanced per (chunk, tier / cell-range).
     - Vertex shader (SPLAT_VERTEX_SHADER in drivers/shaders.rs):
       - Rebuild the axis-aligned face rect from center/normal_axis/size.
       - Backface skip: if face normal points away from camera, collapse the quad
     (output w=0) — halves fill for free.
       - All lighting per-instance, flat: sample uLightVolume (vertex texture
     fetch — WebGL2 guarantees ≥16 vertex texture units), evaluate the same
     ≤4 importance-sorted lights, do the hero-light shadow test (PCF4 from
     shadowVisibility) once at the face center, quantize with the
     existing quantize5 bands. Output one flat color varying.
       - Per-face flat light + face-quantized shadow edges is the voxel look.
     - Fragment shader: fog mix (existing fog/height-fog formulas), ordered
     dither, done. This moves ~200 lines of per-pixel work to per-face work —
     the core Pi win (fill rate becomes trivial for a tiler).
     - Micro-grain near field: a second base mesh — the unit quad subdivided
     N×N (2×2 low spec, 4×4 high). VS hashes each subquad (world pos + subquad
     id) to offset it ±1–2 cm along the face normal and jitter albedo slightly →
     real geometric grain (silhouette + parallax), still opaque quads. Drawn only
     for tier-0 cells within micro_radius (~5–6 u), selected via the per-cell
     ranges. Beyond that, plain quads.
     - Shadow pass: identical to today — render the retained greedy meshes with

     map to 256² behind the high spec profile.
     - Tier selection per frame: distance-based, aligned with the existing
     streaming LOD (fine_distance 15/25 u): tier 0 inside fine ring, tier 1 to
     ~2× fine ring, tier 2 beyond. Reuse mesh_visible-style culling per chunk.

     GPU Microvoxel Face-Splat Renderer (new main renderer)

     Context

     The CPU splatter (wasm_frontend/src/adapters/cpu_splatter.rs) is the visual
     reference: bounded, coarse-to-fine, footprint-driven voxel detail. The main
     GPU renderer (drivers/surface_webgl.rs) is a greedy mesh with a heavy
     per-pixel fragment shader (light-volume sample + 4 lights + PCF shadow +
     fog
     - glow per fragment) — smooth per-pixel gradients make it look less voxel
     than the CPU path, and per-pixel lighting is what kills Pi-class GPUs.

     Goal: a GPU instanced face renderer — flat per-face lighting (the voxel
     look), voxel-lattice albedo grain, the hero shadow map still visible, a
     near-trivial fragment shader, and bounded instance counts — targeting 60
     fps
     on a Raspberry Pi (tile-based GPU, WebGL2) with headroom to grow draw
     distance ("massive scale").

     Defining rule: one instance is one error-selected, axis-aligned visible
     surface rectangle — a greedy-merged face at the chunk's current LOD, capped
     in extent so flat lighting stays honest. Not one instance per voxel face
     (instance-count explosion), and not camera-facing sprites (depth/hole
     artifacts). LOD faces come from the existing world-space at_lod generation,
     never from downsampling a fine grid (which would close doorways and desync
     the shadow caster).

     Selection is amortized, not per-frame: instance pages are built once per
     chunk load/refine (same lifecycle as meshes today; steady-state uploads
     nothing). Per-frame CPU work = frustum/distance cull + choosing prebuilt
     ranges. This preserves the CPU splatter's bounded coarse-to-fine behavior
     while keeping the slow single-threaded wasm CPU off the frame's critical
     path. The CPU splatter itself stays untouched as reference (?renderer=cpu).

     Architecture

     VoxelGrid (fine or coarse via existing GeneratorConfig::at_lod + streaming)
       ─► VoxelMapper greedy quads (existing; already splits by light/AO)
       ─► adapters/face_instances.rs (NEW, portable): MergedQuad →
     PackedFaceInstance,
          extent cap, sorted by 2.5 u sub-cell with (offset,count) ranges
       ─► SurfaceMeshPayload extended (ports.rs) ─► Engine upload (unchanged)
       ─► drivers/splat_webgl.rs (NEW SplatRenderer : RendererPort)
            VS: face rect from center+extents+axis; ALL lighting per-face, flat
            FS: fog + ordered dither + voxel-lattice albedo hash (~15 ops)
            shadow pass: existing greedy-mesh caster into existing depth FBO

     1. Face-instance extraction — wasm_frontend/src/adapters/face_instances.rs 
     (new)

     - Reuse VoxelMapper::map_voxel_grid_with_padding
     (src/adapters/voxel_mapper.rs) exactly as surface_mesh.rs does (same
     halo/seam handling). Emit one instance per MergedQuad instead of 4
     vertices + 6 indices (~10× smaller than the mesh: 16 B vs ~184 B/quad).
     - Extent cap: split quads larger than MAX_FACE_CELLS per axis (~2.5 u
     worth) so one flat light/shadow sample never smears across a wall. The
     mapper's existing light/AO splitting already keeps most faces small.
     - 16-byte instance in application/ports.rs (next to PackedVertex):

     #[repr(C)]
     struct PackedFaceInstance {
         position: [u16; 3], // face-center, POSITION_FIXED_SCALE, chunk-local
         extent_u: u8,       // in voxel cells at this chunk's LOD
         extent_v: u8,
         normal_axis: u8,
         material: u8,
         baked_light: u8,
         ao: u8,
         flags: u8,          // emissive, etc.
         reserved: [u8; 2],
     }

     - Instances sorted by 2.5 u sub-cell; FaceInstanceSet stores per-cell
     (offset, count) ranges for range draws and per-cell culling.
     - LOD comes free from streaming: a coarse-resident chunk (existing
     coarse-first StreamingPolicy + GeneratorConfig::at_lod) yields coarse
     faces from its own grid — same world architecture, seam-safe halo, and the
     same grid feeds its greedy shadow mesh, so visible faces and shadow caster
     agree by construction. No ad-hoc downsampling anywhere.
     - Extend SurfaceMeshPayload with face_instances: FaceInstanceSet (built in
     build_surface_mesh; empty() gets an empty set). Engine untouched — the
     payload rides the existing upload_surfaces flow.

     2. Splat driver — wasm_frontend/src/drivers/splat_webgl.rs (new)

     - SplatRenderer implements RendererPort, uses_surface_meshes() = true.
     - Per chunk upload: instance buffer + retained greedy mesh VBO/IBO (shadow
     caster) + 3D light-volume texture — reuse the upload code pattern from
     surface_webgl.rs::upload_surface; factor link_program /
     camera_matrices into shared pub(crate) helpers.
     - Draw: static unit-quad VBO (divisor 0) + instance attribs (divisor 1),
     draw_arrays_instanced per chunk (per visible cell-range where it pays).
     CULL_FACE enabled; the VS orders corners per normal_axis sign so
     winding is consistent and interior-facing (all six axis cases unit-tested
     against the mesh path's face orientation conventions in surface_mesh.rs).
     - Vertex shader (SPLAT_VERTEX_SHADER in drivers/shaders.rs), all
     lighting once per face, flat (face-center evaluation):
       - Rebuild the axis-aligned rect from center + extents + axis.
       - Sample uLightVolume at face center (vertex texture fetch; WebGL2
     guarantees vertex texture units), evaluate the same ≤4 importance-sorted
     lights, hero-shadow test at face center — tap count per profile (1–2 taps
     low, PCF4 high), reuse shadowVisibility/quantize5 logic.
       - Output flat color + world pos varyings.
     - Fragment shader: exponential/height fog (existing formulas), ordered
     dither, and voxel-lattice albedo grain: hash of world position quantized
     to the voxel grid, small albedo modulation — per-voxel grain on merged
     quads with zero extra geometry. Total ~15 ops (vs ~200 today) — the Pi win.
     - Micro displacement is deferred: no subdivided base quad, no ±cm offsets
     in this iteration (z-fighting/cracks/shadow-detach risk). Revisit later
     behind a flag, inward-only, selected materials only.
     - Shadow pass: unchanged from today — greedy meshes through the existing
     SHADOW_VERTEX/FRAGMENT_SHADER into the existing depth FBO. 128² low,
     256² high profile.
     - Clear color = exact fog color (as today).

     3. Selection, budgets, knobs

     - Per frame: chunk frustum/distance cull (reuse mesh_visible pattern), then
     per-cell range culling for near chunks. No per-frame buffer uploads.
     - Budget rule: profiles carry a face-instance budget; when over budget the
     selector drops whole distant cells to their chunk's coarser payload (or
     skips refinement), never random fine faces — planes stay intact.
